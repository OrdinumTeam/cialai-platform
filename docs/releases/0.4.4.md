## Resumo

Correção do teste do PTY no primeiro uso do Windows, que ficava em "Abrindo…" e não deixava passar do passo do shell. Os apps do celular não mudaram.

## Destaques

* **🪟 O primeiro uso passa do shell no Windows.** O teste do PTY agora responde a pergunta de cursor com que o console do Windows nasce e lê a saída até o fim antes de fechar. Antes ele lia um único trecho e soltava o console sem leitora, e nas versões do Windows anteriores ao 11 24H2 fechar o console espera essa saída ser lida, então o teste nunca voltava.
* **🧹 O prompt aparece limpo.** O texto do teste espera o prompt assentar, com prazo de quatro segundos, e tira o título da janela que o Windows manda antes dele.

## Atualizar

O atualizador embutido encontra sozinho. No macOS e no Linux também vale `curl -fsSL https://cialai.com.br/install.sh | bash`. No Windows, pelo `.exe` ou pelo `.msi`; quem está parado no primeiro uso precisa instalar por cima, porque o atualizador só aparece depois dele.

## Notas da entrega

Os apps do celular não mudaram. Esta entrega sai calada, sem anúncio no Discord.

## Verificação

* **Suíte local.** O `npm test` com Node 22, com os testes de interface e do Rust, e o `clippy` também para o alvo Windows.
* **No Windows.** Os testes do PTY, compilados para Windows neste Mac, passaram na VM com Windows 11 25H2, inclusive um teste novo que abre um shell de verdade pelo ConPTY e exige que o ensaio volte com o prompt e sem a pergunta de cursor.
* **Ainda sem prova.** O travamento não foi reproduzido aqui, porque a VM já tem o console novo, que não espera a saída ser lida ao fechar. O CI no Windows Server 2022, com o console antigo, roda o mesmo teste por disparo manual.
